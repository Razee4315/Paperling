# Paperling: Audit Round 4, the everyday flows (2026-09-26)

*Branch `fix/audit-round4-core-flows-2026-09-26`, cut from `fix/audit-round3-2026-09-25`.*

This round did not hunt for rare edge cases. It looked at the handful of things almost every user does every day, and asked of each one: does it feel as good as Obsidian, Typora or VS Code?

1. Open a note (Welcome screen, Ctrl+O, recents, double-click, drag and drop)
2. Read it (Reader mode, outline, links)
3. Switch to editing, type, and come back (Ctrl+E, split view)
4. Edit lists and tasks
5. Find something in the note
6. Work across a few tabs
7. Save (Ctrl+S, Save As, closing)

**Method.** I added a dev-only fake Tauri backend (`?fakefs=1`). It is an in-memory disk kept in localStorage, so a reload behaves like an app restart. With it, the open/save/tab/conflict flows could be driven for real in the browser for the first time, not just read in code. Every item below marked ✅ was reproduced live, then verified fixed live. Timings come from a dev build, which is slower than the shipped app, so compare the numbers with each other rather than reading them as absolute speeds. I also checked the design against current writing on editor UX (list indentation per CommonMark, line-anchored scroll sync) and Obsidian's and Markdown All in One's list/task behaviour.

**Result:** 18 commits and 574 tests passing (523 at the start of the round). `tsc` is clean.

## 1. Findings in detail

### MODE-01 · P1 · Ctrl+E loses your place ✅

**Where:** `src/hooks/useScrollSync.ts`, `src/utils/scrollSync.ts`, and the scrollers in `CodeEditor.tsx` / `MarkdownPreview.tsx`.

**Repro (before):** open a long note in Reader and scroll to section 400. Press Ctrl+E: the editor showed `## Section 0`. The caret was on some unrelated line, so the first keystroke yanked the view there.

**Why it hurts:** Reader → fix a typo → back is *the* core loop of a reader-first app. Obsidian and Typora keep your position across the switch.

**Fix:** both panes report their top source line on every scroll, even while sync is off. A mode change hands the line to the pane being shown (`sync.handoff`). Entering the editor from the reader also moves an off-screen caret to that line and focuses the editor. A pane that stays visible but changes width (entering or leaving split) re-anchors to its own line.

**Verified:** Reader at line 7218 ("Section 481") → Ctrl+E → the editor top was line 7217, the caret line 7218, and the editor had focus. Editor at line 2999 → Ctrl+E → the Reader showed "Section 200" (line 3001).

### PERF-02 · P1 · The hidden preview froze typing on long notes ✅

**Where:** `src/components/MarkdownPreview.tsx` rendered `<Markdown>{renderedBody}</Markdown>` over the whole body after every debounce. The preview is always mounted, so this also ran in code mode.

**Measured (dev build, 190 kB note):** while typing in *code* mode, `PerformanceObserver` saw two long tasks of **2776 ms and 2486 ms**.

**Fix:** `src/utils/markdownBlocks.ts` splits the body only where CommonMark closes every construct. It never splits inside fences, `$$` math, HTML comments, raw-HTML containers like `<details>`, lists or definition lists. It then groups the blocks into section chunks: a new chunk at each heading, with a soft 3 kB cap. Chunk boundaries depend only on nearby text, so an edit never shifts the other chunks. Each chunk is a memoized react-markdown instance inside a `display:contents` wrapper that carries its line offset. Some constructs are handled document-wide:
- Footnote documents render whole, because numbering spans the document.
- Link reference definitions are shared with every chunk.
- Heading ids are de-duplicated on the DOM across chunks.
- Source lines (scroll sync, outline, goto-line, task checkboxes) add the chunk's offset.

**After:** typing long tasks of **64–106 ms**. The first render of the note took **941 ms** (whole-document render: ~2.7 s).

**Safety net:** a test renders a fixture covering every tricky construct both chunked and whole, and asserts the HTML is identical.

### TABS-20 · P1 · Tab switches lost caret, scroll and undo ✅

**Where:** `CodeEditor.tsx`, the doc-swap effect. It replaced the text wholesale and reset history. `useFileSession` then restored only a *line* number, and placed that line at the top.

**Fix:** a per-tab `EditorState` cache, keyed by tab id, with a `scrollSnapshot()`. A pixel `scrollTop` restored to the wrong place because `setState` rebuilds the height map from estimates. The cache is used only when the text still matches. A stale cache (the file changed while hidden) opens fresh with no history, so undo can never reach into another file (TABS-03 still holds). A same-file reload (external change, "Load from disk") is applied as an edit, so it keeps the caret and is itself undoable.

**Verified:** caret at 301:8 and scroll 8904 were restored exactly, and Ctrl+Z still removed the edit made before the switch.

### EDIT-03/04/05 · P1 · List editing ✅

**Where:** `src/utils/editorActions.ts` (`handleEnter`, `handleTab`).

- **EDIT-03:** the "empty item" check looked only at the text *before* the caret. So `- |task` looked empty, and Enter deleted `- [ ] `. It now checks the whole line.
- **EDIT-04:** Tab now nests the whole item and Shift+Tab un-nests it. The indent is the parent marker's width, because CommonMark needs 3 spaces under `1.`, not 2. Numbered children restart at 1, or continue their sibling's numbering.
- **EDIT-05:** Enter on an empty *nested* item steps out one level instead of ending the whole list (Obsidian, Typora).

### BOOT-01 · P1 data · Tabs opened during session restore were discarded ✅

**Where:** `useFileSession.ts`, boot effect. After awaiting every session file it ran `commitTabs(loaded)` and replaced the live buffer.

**Found live:** with a slow backend, Ctrl+N plus typing during the restore left an editor whose text never reached app state, and the file was saved empty. The restore window is seconds long with many tabs, big files or OneDrive placeholder files. A double-clicked `.md` forwarded by the single-instance plugin also lands in that window.

**Fix:** if tabs already exist when the restore finishes, restored tabs are merged in (skipping ones already open) and the user's tab stays on screen. The regression test holds the restore's reads until the user has typed.

### SYNC-01 · P2 · Split sync drifted ✅
Line-anchored now. The editor maps its top edge to a line via `lineBlockAtHeight`. The preview interpolates between `data-source-line` blocks, with O(log n) rect reads per frame through binary search. The top and bottom snap by fraction, so both ends line up exactly. Verified: both panes showed the end of Section 400 at the top, and Section 401 at the same height.

### PREV-01 · P2 · Bullets vanished next to a task ✅
`index.css` set `list-style: none` on `ul.contains-task-list`. remark-gfm applies that class to the whole list as soon as one item is a task. Now only `li.task-list-item` drops its marker, and the checkbox hangs in the marker gutter (GitHub-style), in exports too. A list of only tasks sits flush. Done tasks are dimmed, and struck through when they have no sub-list.

### FIND-06/07/08/09/10 · P2 · Find ✅
- **FIND-06:** the query is seeded from the selection (one line, escaped when regex is on), in the editor and in reader mode.
- **FIND-07:** a repeat Ctrl+F re-focuses the field.
- **FIND-08:** the active match becomes the editor selection, so Esc leaves you *on* it.
- **FIND-09:** search-as-you-type fires after 90 ms (was 400).
- **FIND-10:** Ctrl+F with focus outside the editor opens the editor's find.

### PANEL-01 · P2 · Side panels behaved like dialogs ✅
New `src/hooks/useSidePanel.ts`, used by the files, outline and backlinks panels:
- Escape closes the panel only when focus is inside it.
- Tab is trapped only on the phone sheet.
- Focus is still returned when the panel closes.
- Outline and palette heading clicks put focus in the visible editor.

### NAV-11 / NAV-12 · Links ✅
- **NAV-11:** Ctrl/Cmd+click in the editor follows `[[wikilinks]]` (with `#heading`), URLs, bare URLs, relative notes and `#anchors`. Other schemes are never followed. A pointer cursor shows while the modifier is held.
- **NAV-12:** `getOpenBuffer` read the live buffer during the render window right after a switch, which still held the previous file.

### SAVE-05 / TABS-22 · Saving and opening ✅
- `src/utils/saveName.ts` suggests the note's frontmatter `title:`, else its first heading, else its first line. Markdown and characters Windows rejects are stripped, and reserved names are refused. The name is offered in the folder you last opened or saved in.
- Save As of a saved file, "Save a copy", and the Open dialog start next to the note.
- Opening a file from an untouched Untitled tab takes that tab's place, with a fresh id so the blank buffer never enters the file's undo history.

### Smaller fixes
- **TASK-01:** Ctrl/Cmd+Enter toggles task checkboxes (see TL;DR).
- **EXPORT-07:** export waits until the preview has rendered the current text (see TL;DR).
- **DLG-01:** the close prompt names the file.
- **A11Y-05:** only the save state is announced, not the whole status bar.
- **"1 word":** fixed the "1 words" plural in the status bar.
- **TABS-21:** double-click the tab strip for a new tab.
- **`<pre>` attribute leak:** code blocks no longer render `node="[object Object]"`.
- **Dev-only:** StrictMode's remount left a stale scroll-frame id, which disabled split sync in dev builds.

## 2. What's already good (don't rework)

- **The file/session layer:** hot exit, conflict parking, and guarded saves all held up under the fake backend. The only gap found was the boot race (BOOT-01).
- **The editor core:** CodeMirror 6 with small, tested pure helpers (`editorActions`). The new list/task logic follows the same pattern.
- **The sanitize pipeline:** `rehypeRaw → rehypeSanitize` is unchanged. Chunked rendering runs the identical plugin chain per chunk.
- **The theme tokens:** the new CSS uses only existing variables and renders correctly in Paper and Graphite.

## 3. Deferred / not changed (and why)

- **Autosave default (off), line numbers (on), spellcheck (off):** these are product defaults and none of them loses data (hot exit covers crashes). I left them as they are. They're worth a deliberate owner decision.
- **The "File saved" toast on every Ctrl+S:** Obsidian, Typora and VS Code show nothing. It's arguably noise, but it's an existing design choice, so I left it.
- **A per-block memoized parse cache:** chunks still create one unified processor each. A future step could share one frozen processor across chunks to cut the first render further. That needs replacing react-markdown's `<Markdown>` with a direct `unified → hast → jsx` path, which is out of scope for a safe round.
- **Rust items from round 3** (`notify` watcher, `expectedMtime` compare-and-swap, hot exit to disk): still deferred. No Rust was touched this round.

## 4. Testing notes for agents

- `node node_modules/vite/bin/vite.js --port 5391`, then open `/?fakefs=1&raf=1`.
- `window.__fakefs`: `write(path, text)` (external edit), `read`, `nextOpen`/`nextSave`/`nextAsk` (dialog answers), `emit(event, payload)`, `reset()`.
- `window.__t`: `open(path)`, `view()` (the CodeMirror view), `pos()`, `tabs()`, `mode("code"|"preview"|"split")`.
- `window.__paperlingScrollSync`: the sync controller (dev only).
- The agent browser pane is often "hidden". Timers are then throttled and **scroll events and frames only happen while a screenshot is being taken**. Use `&raf=1`, and take a screenshot before reading scroll-dependent state.
