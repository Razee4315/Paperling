## 2. Bugs, in detail

### HOT-02 · P0 · Recovered buffer is marked clean, then its backup is deleted ✅ live

**Where:** `src/hooks/useFileSession.ts:1032`
```ts
setContent(activeTab.content);
setOriginalContent(activeTab.content);   // ← should be activeTab.originalContent
```
**Repro (live):**
1. New File, type "Important recovered text", wait 1s.
2. Reload to simulate a crash.
3. The toast says "Recovered 1 unsaved buffer", and the text is back. **But** the tab shows no dirty dot and the status bar says **Saved**.
4. 1.5s later `paperling.buffer-backup.v1` is **gone** from storage.
5. Reload again: welcome screen, and the text is lost for good.

**Why it hurts:** this is the exact case hot exit exists for. After recovery the buffer looks saved, so closing the window **doesn't prompt**, autosave never writes it, and the backup store has already forgotten it. Recovered work survives exactly one more session. The same line affects saved files: a recovered edit to `notes.md` is shown but never saved.

**Fix:**
- Use `activeTab.originalContent`. The tab snapshot on the line above already has it right.
- While there, line 1035 calls `addRecentFile(activeTab.filePath!, …)` even when the active tab is a recovered **untitled** buffer (`null` path). Guard it.
- Add a regression test: boot with an untitled backup and a saved-file backup, then assert `isDirty === true` and that the backup persists after the debounce.

### TABS-17 · P1 · New File does nothing after typing in a fresh Untitled tab ✅ live

**Where:** `src/hooks/useFileSession.ts:531-537` together with `src/utils/tabsModel.ts:156-158`
```ts
const reusable = findReusableUntitledTab(tabsRef.current);   // reads SNAPSHOTS
if (reusable) { if (reusable.id !== activeTabIdRef.current) activateTab(reusable.id); ... return; }
snapshotActiveTab();                                          // too late
```
The active tab's stored snapshot is still the empty one it was created with (snapshots only update on switch). So it counts as "reusable", and New File returns early without doing anything.

**Repro (live):** Welcome, then **New File**, type anything, then click the tab bar **+**, the palette "New file", or press Ctrl+N. You still have one tab.

**Why it hurts:** the most common first-run flow (open the app, jot a note, want a second note) silently fails.

**Fix:** call `snapshotActiveTab()` before `findReusableUntitledTab` (as `openTutorial` already does), or pass the live state to the helper. Add a test.

### SLASH-02 · P1 · Slash menu hijacks Enter on existing prose ✅ live

**Where:** `src/components/CodeEditor.tsx:538-558`. The SLASH-01 self-heal runs from `detectSlash`, which is called on **every selection change** (`:423`), not only on typing.

**Repro (live):**
1. Put the text `Run the command /table later` in the editor.
2. Place the caret right after `/table` (click or arrow keys). The **slash menu opens**.
3. Press Enter. The document becomes `Run the command | Header 1 | Header 2 |\n| --- | --- |…later`.

**Why it hurts:** clicking at the end of any ` /word` that matches a command (`/code`, `/quote`, `/h1`, `/task`, `/table`, `/math`, and so on) arms a silent text rewrite on the next Enter. Writers of technical notes (`see /code`, CLI docs) will hit it.

**Fix:** only run the self-heal branch when `update.docChanged` and the change was a user insertion ending at the caret (`tr.isUserEvent("input.type")`). Don't run it on pure selection updates.

### SHC-09 · P1 · Alt+←/→ tab switching is dead inside the editor (Windows/Linux) ✅ live

**Where:** `src/hooks/useGlobalShortcuts.ts:164-172` together with the SHC-01 guard at the top of the handler, and `src/components/CodeEditor.tsx:476` (`defaultKeymap`).

CodeMirror's `defaultKeymap` binds **`Alt-ArrowLeft/Right` → `cursorSyntaxLeft/Right`** (on non-mac). It handles the key and calls `preventDefault`. The window handler now bails on `e.defaultPrevented`, so the tab never switches.

**Live measurement:** a window bubble listener saw `defaultPrevented: true`, the caret moved 5→4, and the active tab didn't change. Tab switching only works when focus is outside the editor (reader mode).

**Why it hurts:** `TEST-CHECKLIST.md` tells the owner "Windows/Linux: Alt+←/→ switches tabs as before". That's false in code/split mode, which is where people type.

**Fix:** on non-mac, add `Alt-ArrowLeft/Right` to the editor's `Prec.highest` `editingKeymap`, dispatching the existing tab-cycle action. Or filter those two entries out of `defaultKeymap`.

### EXT-04 · P1 · A tab switch resolves the conflict dialog as "keep mine" 📖 code

**Where:**
- `src/hooks/useFileSession.ts:214-218` (`applyTabToLive` → `setConflictPrompt(null)`, with the comment "resolves it as keep mine")
- `src/components/Modal.tsx:55-62` (listens for Escape only; doesn't stop other keys)
- `src/hooks/useGlobalShortcuts.ts` (no "modal open" gate)

**Scenario:**
1. File A is dirty, and another program saves A.
2. You focus Paperling. The **conflict dialog** appears, and autosave is paused.
3. You press **Alt+→ / Ctrl+Tab / Ctrl+Shift+T / Ctrl+O** (all still live behind the modal).
4. The tab switches. The dialog vanishes with no choice made. A is now a **dirty background tab whose `knownMtime` already equals the external mtime**.
5. The background autosave pre-write stat sees nothing new, so **1.5s later it overwrites the external version.**

This is the same class as the Escape bug EXT-02 fixed, reached through a different door.

**Fix:**
- When leaving a tab with an open `conflictPrompt`, **add its path to `parkedAutosavePathsRef`** instead of clearing the conflict. The existing EXT-03 machinery then re-raises the dialog when you come back.
- Separately, make `useGlobalShortcuts` ignore everything except F11 while any `aria-modal` dialog is open.

### EXT-05 · P1 · The background focus check undoes EXT-03 parking 📖 code

**Where:** `src/hooks/useFileSession.ts:837-846`. For a dirty background tab whose file changed, the focus handler **advances `knownMtime` to the new disk mtime** and toasts "Saving it will overwrite those changes". The background-autosave effect (keyed on `tabs`) then re-runs, its `info.modified > knownMtime` check is now false, and it writes the buffer over the external change. The only feedback is a toast saying that's about to happen.

**Race window:** switch away from dirty A, then edit A externally and return within 1.5s. This is realistic with sync tools, or with "save in VS Code, alt-tab back".

**Fix:** in that branch, park the path (`parkedAutosavePathsRef.add`) and **don't touch `knownMtime`**. Then the same conflict flow applies on activation. Add a test alongside the EXT-03 ones.

### GS-04 · P1 · Replace-in-files is silently reverted for open files 📖 code

**Where:**
- `src/components/GlobalSearch.tsx:147-184` (reads and writes **disk**, ignoring open buffers)
- `src/App.tsx:2021-2033` (`onFilesReplaced` only looks at the **active** file, and only warns if it's dirty)
- `src/hooks/useAutosave.ts:67-70` (active-tab autosave has **no pre-write mtime check**, unlike the background path)

**Scenarios:**
- **Active file dirty:** the replace writes to disk. You get an info toast "review before saving". Active autosave fires ≤1.5s later and writes the old buffer back. The replacements for that file are gone, but the success toast said "Replaced N matches".
- **Clean background tab:** its snapshot still holds the pre-replace text. Its mtime is only rechecked on window *focus*. Switch to it and type one character: active autosave writes the stale text + edit over the replaced file.

**Fix:**
- For each file open in a tab, apply the replacement **to the buffer** (the tab snapshot, or live state for the active tab), not to disk. Or refuse and list those files.
- Refresh clean background tabs from disk after the replace.
- Most importantly, give the **active** autosave the same pre-write `get_file_info` guard the background path has. That turns this whole class of bugs (external editors too) into the conflict dialog instead of an overwrite.
- Long-term: `save_file(path, content, expectedMtime)` compare-and-swap in Rust.

**GS-04b (P2, same component):**
- The replacement **can't be empty** (`disabled={… || !replacement}` at `:251,:266`), so "delete every occurrence" is impossible.
- Results are capped at **300 files / 50 matches per file** (`commands.rs:530-532`), but "Rewrite 300 files?" doesn't say it's partial.
- Enter in the replace field opens a search result instead of doing anything useful.
- There's no undo. Keep the pre-replace contents in memory for a one-click "Undo replace".
- `.txt` files the app opens are excluded from search.

### HOT-03 · P1 · Discarded edits come back on the next launch 📖 code

**Where:** `src/App.tsx:717-720` (`handleDiscardAndCloseWindow`) and `:657-691` (`handleSaveAndCloseWindow`). Both call `forceCloseWindow()` straight away. The backup store (`paperling.buffer-backup.v1`) is only rewritten by an 800ms debounce, which never runs because the window is destroyed first.

- **Discard:** next launch says "Recovered N unsaved buffers" and brings back exactly the text the user chose to throw away. For saved files it shows as dirty over the disk content.
- **Save all:** saved-file backups are harmless (backup == disk content, so they're skipped). But **untitled buffers just saved to a new path** come back as phantom Untitled recoveries.
- **Fix:** call `saveBufferBackups([])` (or save the post-save set) before `forceCloseWindow()` on both paths. Test both.

### HOT-04 · P1 · Recovery ignores disk changes made after the crash 📖 code

**Where:** `src/hooks/useFileSession.ts:969-978`. The only check is `backup.content !== fileData.content`. The backup stores `originalContent` (the disk text the edits were based on), but it's never compared with the **current** disk text.

**Scenario:** crash, then you edit the file in another editor, then relaunch. Paperling puts the pre-crash buffer over it. Today HOT-02 hides this, because the tab shows clean and the stale text is only written if you edit. Once HOT-02 is fixed, autosave would write the stale buffer over the newer disk version.

**Fix:** if `backup.originalContent !== fileData.content`, open the tab with the backup as the buffer **and** park the path, so the conflict dialog (Keep mine / Load from disk / Save a copy) decides. That's the existing EXT flow.

### HOT-05 · P2 · Hot-exit store: quota failure keeps a stale snapshot 📖 code

**Where:** `src/utils/bufferBackup.ts:54-66`. Up to 20 × 1M chars can be requested, but WebView2's localStorage allows about 5MB per origin, shared with AI chat sessions and settings. When `setItem` throws, the catch **leaves the previous value in place**. After a crash, older text is "recovered" over newer saved work (see HOT-04).

**Fix:**
- On a quota error, `removeItem` and retry with the newest/smallest buffers until one fits.
- Better: back up to an app-data file via a Rust command (no quota, survives a WebView2 profile reset). Rust work is deferred per AGENTS §2.5.

### AI-06 · P1 · The AI bubble writes to stale offsets, possibly in another file 📖 code

**Where:** `src/components/CodeEditor.tsx:1114-1126`. `onReplace` and `onInsert` dispatch at `aiBubble.selStart/selEnd`, captured when the bubble opened. Nothing maps these through later edits, and **nothing closes the bubble on `docSwapId`**.

**Scenarios:**
- Select a paragraph, Alt+J, then Rewrite. While it streams, type above the selection. Replace now splices at shifted offsets and deletes the wrong text.
- Or switch tabs mid-stream. Replace writes into the **other file** at the first file's offsets, and autosave persists it.

**Fix:**
- Store the range as a CodeMirror `StateField`/`RangeSet` so it's mapped through every transaction.
- Before replacing, check that `sliceString(from,to) === aiBubble.text`; if not, show "the selection changed — insert at cursor instead?".
- Close the bubble in the `docSwapId` effect.

### MMV-04 · P2 · The fullscreen button covers Zoom-in ✅ live

**Where:** `src/components/MermaidBlock.tsx:146` (toolbar `absolute top-2 right-2`) and `:307` (fullscreen button, also `absolute top-2 right-2`, later in the DOM).

**Live measurement:** Zoom-in is at (608,232,28×28) and fullscreen at (611,229,28×28). `elementFromPoint` at Zoom-in's centre returns **"View diagram fullscreen"**. Clicking **+** opens fullscreen.

**Fix:** put the fullscreen button inside the toolbar as a fourth button (simplest), or offset it (`right-[7.5rem]`).

### MMV-05 · P2 · Broken diagrams leak DOM nodes into `<body>` ✅ live

**Where:** `src/components/MermaidBlock.tsx:242-257`. When `mermaid.render` fails it leaves its temporary `#d<id>` container (with a full `<style>` block) appended to `document.body`. Live: after one syntax error, `body > #dpaperling-mermaid-5` was present. Each failed render while typing a diagram leaks another node plus stylesheet.

**Fix:** in `.catch`, `document.getElementById("d" + idRef.current)?.remove()` (and the same for `#` + id). Also give each render attempt a fresh id.

**Carry-over, still open:** the SVG cache key is `theme+code`, so the same diagram twice reuses an SVG with the **same element id**. In fullscreen the SVG is also duplicated with the same id. Suffix ids per instance.

**Improvement:** fullscreen only fits to natural width. It should fit to the viewport (both axes), so small diagrams scale up and tall ones fit.

### ENC-01 · P2 · A UTF-8 BOM breaks frontmatter and the first heading ✅ live

**Where:** `src-tauri/src/commands.rs:267` (`read_to_string` keeps U+FEFF) and `src/utils/frontmatter.ts` (anchored `^---`). There's no BOM handling anywhere in `src/`.

**Live:** `\uFEFF---\ntitle: BOM test\n---\n# Heading` renders as `<hr>` plus `<h2>title: BOM test</h2>`, with no frontmatter card. Notepad, older Office tools, and many Windows exporters write BOMs.

**Fix (JS-only, no Rust needed):**
- Strip a leading `\uFEFF` in `loadFileDirect` and the boot restore, and remember `hadBom` on the tab.
- Re-prepend it in the save paths so the file round-trips byte-identically.
- Later: detect UTF-16 and non-UTF-8 in Rust and show a friendly error (today it's the raw `stream did not contain valid UTF-8`).

### NAV-09 · P2 · Heading and block wikilinks become filenames ✅ live

**Where:** `src/components/MarkdownPreview.tsx:242-252` (the `WIKILINK_RE` target keeps `#…`) and `src/App.tsx:771-806`.

**Live:** `[[Other Note#Section]]` renders with target `Other Note#Section`. Clicking it probes `Other Note#Section.md` and then offers **"Create Other Note#Section.md?"**. This is the most common Obsidian link form after plain `[[Note]]`.

**Fix:**
- Split the target on the first `#` into `file` + `anchor`, open the file, then scroll to the `slugify(anchor)` heading (the unicode slug from round 1 already exists).
- `[[#Heading]]` (same-file) should just scroll.
- `^block` refs can scroll to the line containing `^id`.

## 4. Improvements vs Obsidian / Typora / VS Code (ranked by impact)

1. **One conflict model instead of four.** Today there are four separate paths: the active autosave (no guard), background autosave (guarded), the focus watcher, and replace-in-files. EXT-04/05, GS-04, and CLOSE-02 all come from these disagreeing. Proposal:
   - `save_file(path, content, expectedMtime)` compares-and-swaps in Rust.
   - Every writer passes the tab's `knownMtime`.
   - A mismatch always parks the tab and raises the dialog.
   - Add a real `notify`-crate watcher so changes are seen without an alt-tab.
2. **Hot exit to disk:** move the store to `app_data_dir/backups/*.json` via Rust (no quota, one file per buffer, atomic). Pair it with HOT-02/03/04.
3. **Explorer file operations + open-folder workspace** (unchanged top gap from round 1; needs Rust).
4. **Obsidian link fidelity:** `[[Note#Heading]]`, `[[#Heading]]`, `^block` refs, callouts, `#tag` pills with a tag search, `%%comments%%`. Most of this is remark-plugin work, no Rust.
5. **Search upgrades:** regex and whole-word toggles, include `.txt`, a per-file replace preview with checkboxes, "Undo replace", a result count that admits truncation.
6. **Editor staples:** Ctrl+D multi-select, Ctrl+G go-to-line, font-size setting wired to the editor, readable line length for the **editor** too (today it only centres the preview).
7. **Keybinding customization UI** (round 1 §5 #6; the infrastructure is ready).
8. **Quick switcher** (fuzzy over folder files, not just recents/tabs).
9. **Mermaid:** fit-to-screen fullscreen, keyboard zoom (+/−/0 when the diagram is focused), export diagram as SVG/PNG.
10. **Test infra:** `vmThreads` pool (roughly 4× faster CI) and a Playwright smoke test driving the web build (New File, type, reload, recovered-and-dirty). That one test would have caught HOT-02 and TABS-17.
