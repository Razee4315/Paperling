## Blocking findings

### PR #263 — P0: active reload discards edits made during a pending read

Evidence: `src/hooks/useExternalChangeWatcher.ts:58` and `src/hooks/useFileSession.ts:327` at `ed2fce60`.

```ts
if (!isDirtyRef.current) {
    await reload(path);
}
```

The cleanliness check precedes asynchronous I/O. The reload applies the returned file without validating that the same tab and buffer revision are still current. Reproduction: start a clean-file reload, type before the read finishes, then resolve the read. The new text is replaced by the external text.

**Fix:** use a dedicated reload transaction. Capture tab identity and buffer revision, then revalidate after the read along with review/conflict state. If anything changed, retain the buffer and surface a conflict. Add the deferred-read regression permanently.

### PR #263 — P0: pending autosave writes while an external conflict awaits consent

Evidence: `src/hooks/useExternalChangeWatcher.ts:57`, `src/hooks/useFileSession.ts:713`, `src/hooks/useAutosave.ts:76`.

```ts
lastKnownMtimeRef.current = info.modified;
```

The watcher accepts the external mtime before the user accepts the external contents. An already-running autosave stat can then pass against that newly absorbed timestamp and call `save_file` while the conflict dialog is still pending. The deferred-I/O test observes that write without consent.

**Fix:** keep observed-but-unaccepted disk state separate from the accepted save baseline. Recheck cancellation, active path and conflict state immediately before writing. Preserve the user's explicit conflict choice; never auto-resolve destructively.

### PR #263 — P1: stale stat switches the user back to the previous tab

Evidence: `src/hooks/useExternalChangeWatcher.ts:53`.

```ts
const info = await invoke<FileInfo>("get_file_info", { path });
```

After this await, the watcher does not establish that `path` still identifies the active document before invoking reload. Start stat for A, switch to B, then resolve A's stat: A becomes active again.

**Fix:** validate captured identity after each await; discard stale results. Include the tab-switch regression.

### PR #263 — P0: background reload discards edits made after its pre-read check

Evidence: `src/hooks/useFileSession.ts:1004` (application at `:1009`).

```ts
const fileData = await readTextFile(path);
```

The background path checks the snapshot before reading, then updates it without validating it again. Start a reload of background A, switch to A, edit, switch back to B, then finish the read. A's edits become external text and the tab becomes clean. This fourth reproduction is new to this review.

**Fix:** capture and revalidate the background tab's revision and dirty state after reading. Preserve changes and park a conflict if the snapshot changed.

**Attribution:** these unsafe helpers largely predate #263. Its new 1.5-second polling exposes them during normal in-focus editing; this review does not claim every unsafe helper line was introduced by the PR. The tab-drag improvement can be split into a separate, verified change.

All four safe-behavior assertions fail on the current PR head. [Reproduction source](review-evidence/2026-10-08/pr263.reload-race.test.ts.txt) is stored outside test discovery. Copy it into `src/hooks/pr263.reload-race.review.test.ts` in an isolated checkout of #263 to reproduce; it intentionally fails on this head. [CI](https://github.com/Razee4315/Paperling/actions/runs/37292089048) and [Android](https://github.com/Razee4315/Paperling/actions/runs/37292088027) require action rather than passing. The [older Windows Test Build](https://github.com/Razee4315/Paperling/actions/runs/37314535285) is a build of unsafe code, not evidence of safe file handling.

### PR #266 — P2: concurrent refresh creates untracked object URLs

Evidence: `src/utils/localImageCache.ts:39`, `:46`, `:48`, `:50` at `88007791`; focus subscription `src/components/MarkdownPreview.tsx:407`.

```ts
entries.delete(key);
// ...
revokeUrl(hit.url);
const buf = await read(baseDir, relPath);
const url = createUrl(new Blob([buf], { type: mimeType }));
entries.set(key, { url, mtime });
```

Every rendered reference refreshes on focus. The first call removes the cache entry before awaiting its replacement; simultaneous callers each read the same image and overwrite the one Map entry. Their earlier URLs are no longer tracked for eviction/revocation. A probe using the actual helper, one preloaded SVG, 50 concurrent references, and three changed-mtime refreshes produced **151 URLs, 3 revocations and 147 untracked URLs** (one additional URL remains correctly cached).

The initial-miss race existed before this PR; repeating it after every regeneration/focus is the new impact. This matters for large notes and long-running sessions, especially with images up to the backend's 25 MB limit.

**Fix:** coalesce requests behind one per-key in-flight promise, atomically install one successful replacement, and revoke the superseded URL. Add concurrent initial-load and concurrent-refresh regressions.

### PR #266 — P2: temporary read failure destroys the previous usable image

Evidence: `src/utils/localImageCache.ts:39` and `:46`, `src/components/MarkdownPreview.tsx:474`.

```ts
revokeUrl(hit.url);
const buf = await read(baseDir, relPath);
```

A read failure after a successful changed-mtime stat has already destroyed the fallback. The component displays a failure placeholder. A simulated sharing violation confirms the old URL is revoked. External image generators can briefly lock or replace files, making refresh an especially relevant time to preserve the last usable image.

**Fix:** retain the old cache entry until replacement succeeds; keep the previous image on a transient refresh failure and retry on a later refresh. Add a failed-refresh regression.

Typecheck passed; **29/29 focused tests passed** (5 cache and 24 preview). Passing sequential tests do not cover the reproduced concurrency case. [CI](https://github.com/Razee4315/Paperling/actions/runs/37598347223) and [Android](https://github.com/Razee4315/Paperling/actions/runs/37598346423) are `action_required`, not green and not ordinary assertion failures. Keep backend containment validation unchanged.

### PR #265 — P1: duplicate CodeMirror types break compilation

Evidence: `bun.lock:126`, `:128`, `:1294`, `:1296`; compile diagnostic includes `src/components/CodeEditor.tsx:531`.

```text
root:   @codemirror/state 6.7.6; @codemirror/view 6.43.13
nested: @codemirror/state 6.7.5; @codemirror/view 6.43.7
Types have separate declarations of a private property 'flags'.
```

[All desktop platforms](https://github.com/Razee4315/Paperling/actions/runs/37381580286) and [Android](https://github.com/Razee4315/Paperling/actions/runs/37381579437) fail. Users cannot receive a build. Separately, [Nix](https://github.com/Razee4315/Paperling/actions/runs/37381579484) reports a fixed-output hash mismatch; the dependency hash in `flake.nix:28` must match the final lockfile.

**Fix:** align/deduplicate the CodeMirror dependency family and overrides, regenerate the Bun lockfile, then update the Nix dependency hash. Require all affected platforms green. Also resolve or verify the KaTeX split: root 0.19.0 CSS/runtime versus `rehype-katex`'s nested 0.16.45 (`bun.lock:1378`). That split is observed; an actual rendering regression was not demonstrated here. Prefer a separate KaTeX upgrade with math/chemistry/export verification.

### PR #260 — P1: Windows COM dependency versions disagree


**Fix:** upgrade/adapt both the bridge and direct PDF bindings together, or retain the compatible Tauri family. Require Windows x64/ARM compilation and native PDF export verification. No speculative Rust fixes were made locally.

### PR #246 — P1: Astro checker does not support the submitted compiler

**Fix:** keep the docs compiler on its supported version until checker/language-server compatibility is established. Do not remove the checker merely to turn the workflow green.

## PR #264: why it can merge

`docs/package.json:31` changes `@types/node` to `^26`, with corresponding docs lockfile and `undici-types` updates. It does not change the app runtime or source. [Website CI](https://github.com/Razee4315/Paperling/actions/runs/37381341786) reports 33 checked files, zero errors, five tests passing, 21 built pages and successful verification; [app CI](https://github.com/Razee4315/Paperling/actions/runs/37381342587) passes across all four platforms and security jobs.

The workflows run Node 24, so Node 24 typings would be a closer model and avoid accidentally accepting Node 26-only APIs in future code. No current unsupported API or runtime failure was demonstrated. This is a P3 maintenance recommendation, not grounds to label this tested, types-only PR broken.

Preserve the raw-HTML sanitization order, path containment, atomic-save design, conflict consent UI, platform-aware keybindings, theme architecture and the extracted image-cache tests. #266 retains validated backend image reads; its cache concurrency needs repair, not a broader filesystem permission change.

1. Merge #264 if desired; optionally align typings in a separate maintenance change.

User-configurable shortcuts and richer workspace/graph navigation remain broader product backlog, not reasons to delay a safe types-only PR.
